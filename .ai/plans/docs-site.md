# Docs site parity plan

Goal: every page of the Material React Table docs (`apps/material-react-table-docs`, MRT v3 at
commit 6008059, untracked reference copy) exists in `apps/shadcn-react-table-docs` with the same
content, rendered with SRT code. Started 2026-10-17 after the fumadocs scaffold, theme and the
first four pages (index, install, usage, pagination; commits 275bdf5 to 6d5919b).

## Starting point (measured 2026-10-17)

- MRT pages: 100 MDX files. `docs/index` 1, `getting-started` 4, `guides` 39, `examples` 41,
  `api` 10, `blog` 2, root 3 (about, changelog, roadmap). Plus `pages/index.tsx` (home page).
- MRT examples: 113 folders under `examples/`, each `sandbox/src/TS.tsx` (11106 lines total),
  12 tabbed groups under `example-groups/` used by 52 pages.
- SRT docs today: 4 pages, 3 examples (basic, alternate-pagination, remote), prop tables
  TableOptions and StateOptions, `scripts/sync-mrt-docs.mjs` (page sync, name map, `prop-tables`
  mode), `scripts/check-pages.mjs` (dev-server Playwright gate), theme with 6 presets.

## Definition of "same content, SRT code"

Per page, compared against the MRT twin:
- Same path and slug, same frontmatter title and description (from MRT's `<Head>`), same headings
  in the same order, same prose apart from the name map, same example and prop-table tags in the
  same places.
- Generated through `scripts/sync-mrt-docs.mjs`, never hand-edited. A page that needs a change the
  name map cannot express gets a per-path rule in the script, so a re-sync replays it.
- Examples: `examples/<name>/TS.tsx` + `index.tsx`, same columns, data, options and handlers as
  MRT's `sandbox/src/TS.tsx`; `mui*Props` to `srt*Props`, `MRT_*` to `SRT_*`, MUI parts to the
  shadcn part with the same role (as in the stories plan), faker seeded (`faker.seed(<n>)`) because
  pages are server rendered. Example groups: one tabbed component per MRT group, shadcn `Tabs`.
- A story MRT has that SRT cannot run because the library lacks the feature: port as written, log
  the gap in the tracker. The library is not edited from this plan.
- Denylist (facts differ from MRT, synced once then fixed by a per-path rule, listed in the
  ATTENTION file for the owner): `getting-started/install`, `getting-started/usage`,
  `api/index`, `guides/localization` (install command), home page.
- Skipped, not ported: `blog/*`, `about`, `changelog`, `roadmap`, `getting-started/migrating-to-v3`.
  Redirects from MRT's `next.config.js` are kept in `next.config.mjs`.

## Shared files and ownership

Clusters run in parallel on one working tree. Shared files are append-only and regenerated, never
hand-merged:
- `scripts/sync-mrt-docs.mjs`: name map and per-path rules, append only; `git pull --rebase`
  before every commit.
- `examples/registry.ts`: generated by `scripts/build-example-registry.mjs` from
  `examples/*/index.tsx` and `example-groups/*.tsx` (export name = PascalCase of the folder name
  + `Example`, groups keep their file name). `components/mdx.tsx` spreads it. Nobody edits
  `registry.ts` by hand.
- `scripts/check-pages.mjs`: PAGE_CHECKS moved to `scripts/page-checks/<cluster>.mjs`, globbed.
- `content/docs/**/meta.json`: generated by the sync script only.
- An example folder is created by the cluster that owns the first page importing it (cluster
  order A to E). Another cluster that needs it and finds it missing creates it too; on rebase
  conflict the earlier commit wins.

## Clusters

A. `api/*` (10 pages) + `getting-started/index`: remaining prop-table data (columnOptions, table/
   column/row/cell instance APIs) through the `prop-tables` mode, their table components, the
   `*Source` components, `example-groups/OptionsSwitcher`, `InstanceAPIsSwitcher`.
B. `guides/` accessibility to display-columns (20 pages, alphabetical) and their examples.
C. `guides/` editing to virtualization (19 pages) and their examples, including
   `LocaleExamples` with the 37 `localization-i18n-*` folders (one file each, generated from the
   template of the first one).
D. `examples/` pages advanced to export-pdf (22 pages) and their example groups.
E. `examples/` pages faceted-values to virtualized (19 pages), their groups, and the home page
   (`app/(home)/page.tsx` from MRT's `pages/index.tsx`: hero, install command, HomeCards,
   FeatureTable, ComparisonTable as static content; StatBadges, Contributors, EthicalAd dropped).

## Method per page

1. Run `node scripts/sync-mrt-docs.mjs <path>`; read the output against the MRT source.
2. Port the examples and groups the page imports. Check every `srt*Props`, `SRT_*` name against
   `packages/shadcn-react-table/src/components/ui/shadcn-react-table/types.ts`.
3. Add the page to `scripts/page-checks/<cluster>.mjs`: no console or page errors at 1440 and
   700, each example renders a table with rows, prop tables render rows, feature markers as the
   page dictates.
4. Gates: `pnpm prettier --write` on files written, `pnpm --filter shadcn-react-table-docs
   types:check`, `node scripts/check-pages.mjs <cluster>` green against a dev server on the
   agent's port (5322 to 5329; never 3000, 5173, 5273, 6006, 6306).
5. One commit per page or per small batch: `docs: <group>/<page>`, body lists examples ported
   and gaps. Push after each. No trailers, no attribution.

## Verifier pass

After all clusters: `scripts/docs-diff.mjs` compares, per MRT page, the heading list and the
component tag list (examples, prop tables, groups) with ours; zero differences except the skipped
pages and the denylist rules. `pnpm --filter shadcn-react-table-docs build` passes.
`node scripts/check-pages.mjs` over every cluster green. Then an adversarial verifier workflow,
one agent per page, refuting "same content, SRT code"; confirmed deviations fixed by a fixer agent.

## Tracker

`.ai/plans/matching/docs-parity-notes.md`: one `### [ ] <path>` per page, ticked by the owner
only. Under each entry at most 3 bullets: examples ported, library gaps, commit. Library gaps also
under `## Library gaps` at the end.

## Out of scope

Library changes, Vercel deploy, DocSearch, Plausible, sitemap, blog, i18n of the docs UI.
