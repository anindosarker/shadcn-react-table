(a08daab). Merged onto `claude/review` only after the v0.2.0 PR (#19) is merged, so the release
under review does not move. The TanStack v9 port starts from the result.

Phases: [01 shared source and overrides](01-shared-source.md),
[02 registry folder](02-registry-folder.md), [03 docs app rename](03-docs-rename.md),
[04 integration](04-integration.md).

## Why (owner review, 2026-10-19)

- 105 of the 128 library files are byte-identical in `bases/radix` and `bases/base`; only 23
  differ. Two full trees mean every shared fix lands twice and `diff-bases` exists only to
  police that. shadcn's repo duplicates too (same blobs in `bases/*/hooks`, `bases/*/lib`);
  that is not a reason to copy the cost.
- `bases/*/package.json` (`shadcn-table-radix`, `shadcn-table-base`, `private`) and
  `bases/*/tsconfig.json` are stubs so the shadcn CLI can run inside the tree. They read as a
  monorepo inside the monorepo. Nothing else uses them.
- Registry code sits in three places: `packages/shadcn-table/scripts/*`,
  `apps/shadcn-table-docs/scripts/build-registry-items.mjs` and
  `scripts/build-example-registry.mjs` (which is not a registry at all), root `registry.json`.
- `tsconfig.app.json` means the Radix tree and `tsconfig.base.json` the Base UI tree; the
  conventional reading of both names is different.
- `apps/shadcn-table-docs` repeats the repo name.

## Decision

- One copy of every shared library file in `packages/shadcn-table/shared/`; per-base folders
  hold only what differs. Resolution by ordered alias search (base folder first, `shared/`
  second) in TypeScript `paths` and a small Vite resolver; no generated tree, no symlinks, no
  runtime adapter. Library files import each other through the `@/` alias, never relatively.
  Installed output is unchanged: both editions land in `components/ui/shadcn-table/` with the
  same relative paths, the CLI rewrites `@/` as it does for every shadcn part.
- Per base stays: `components/ui/*` (shadcn parts), `lib/utils.ts`, `index.css`,
  `components.json`, `registry.ts`, and the override files under
  `components/ui/shadcn-table/`. The override folder listing is the complete list of
  differences; `diff-bases.mjs` is removed.
- All registry code in `packages/shadcn-table/registry/`. Committed catalogs stay next to the
  files they list because the CLI resolves `files[].path` relative to the catalog: root
  `registry.json` (the `include` file the GitHub address form reads),
  `packages/shadcn-table/registry.json` (library items), `apps/docs/registry.json` (example
  items). Scripts, not catalogs, were the sprawl.
- Docs app folder `apps/docs`; package name `shadcn-table-docs` unchanged. Docs keep the two
  installed library copies (`components/ui`, `components/ui-base`) via `lib:install`; the
  docs are the one project that needs both editions at once and installing is the simplest
  way to have them.
- `tsconfig.app.json` becomes `tsconfig.radix.json`, `tsconfig.base.json` becomes
  `tsconfig.baseui.json`; scripts `tsc:radix` / `tsc:baseui` (keep `tsc` as an alias of
  `tsc:radix` so CI and docs do not change in the same PR).

## Non-goals

- Behaviour changes in the library, stories or docs. Same 400 stories pass on both bases,
  same 76 + 114 items, same install targets.
- Sharing the shadcn parts between bases (they are the thing that differs).
- The docs app importing the trees directly instead of installing them.
