## Dependencies and parallelism

```
01 release automation ──┐
02 docs weight ─────────┼── independent, start together
03 PostHog ─────────────┤
04 package layout ──────┘──▶ 05 docs app layout ──▶ 06 v9 architecture
```

- 01, 02, 03 and 04 run at the same time, one worktree and branch each under
  `shadcn-react-table.worktrees/<phase>` on `v0.4/<phase>`.
- 05 starts when 04 is merged: the docs installer reads the registry from the new tree.
- 06 starts when 05 is merged: every rewrite edit lands once on final paths. Its phase 00
  (comparison, read-only) may start as soon as 04 is merged.
- 02 and 05 both touch `example-snippet.tsx`, `example-playground.tsx`, `code-explorer.tsx`
  and `lib/example-variants.mjs`. 02 merges first; 05 rebases on it.
- 03 and 05 both touch `components/base-selector.tsx` and `components.json` neighbours. 03
  merges first.

## Integration

- Work branches merge into `claude/review` with a merge commit after the phase's gates are
  green in CI. `claude/review` merges into `master` at each milestone below; Vercel deploys
  `master`.
- Milestones: after 01 to 04 (docs lighter, analytics live, release path proven), after 05,
  after 06. Tags: see "Open".
- Each phase file ends with its gates. Repo-wide gates for every merge: `pnpm format` check,
  `tsc:radix`, `tsc:baseui`, stories tsc, `lint`, `test` and `test:base`, Storybook builds,
  docs `types:check`, `lint`, `build`, `check-pages.mjs`.

## Workflow

One Workflow run per phase, resumable. Per phase: a coder agent in the worktree, a reviewer
agent that walks the plan file top to bottom and refutes the coder's report, a gate agent
that runs the phase's gates and the repo-wide gates on the merged result. Up to 3 bounces
between coder and reviewer. 06 has its own cluster pipeline, see its file. The lead merges
and writes the tracker.

Halt and ask the owner on: a public API or naming choice not covered by the decisions, more
than 3 bounces, an unfixable gate, a finding that contradicts a recorded decision.

## Process rules (from `CLAUDE.md`, the user's global rules and the handoffs)

- No `git add -A`, no commit trailers or attribution, push right after every commit, no
  comment-only or format-only commits, format once before each commit.
- Ports never to use: 3000, 5173, 5273, 5320, 5404, 5406, 6006, 6007, 6306. Never `pkill`;
  stop only processes you started, by PID.
- Revert `lib:install` side effects (`app/global.css`, `tsconfig.json` `.next-*` entries)
  before committing.
- Browser checks with Playwright from `packages/shadcn-table/node_modules`, never from
  screenshots.
- Tracker per phase: `<phase>-tracker.md` next to the plan, decisions and deviations only.
