# v0.2: Base UI support

Status: planned 2026-10-19. Not started. Order agreed with the owner: Base UI before TanStack
Table v9 and before React Aria.

## Why

shadcn `init` defaults to `--base base` (Base UI) since 4.x. Every new shadcn project is on a
base the table does not support, and the install docs force `--base radix`. The install test
`existing` scenario and the earlier style work both recorded the failure mode: the library files
type-check against the Radix parts only; on `base-nova` the Base UI tooltip, menu, select,
checkbox and slider props differ.

## Facts

- The library imports 24 shadcn parts from `@/components/ui/<part>`; the registry item lists
  23 of them as bare `registryDependencies`, so `shadcn add` installs the consumer's own base
  variant of each part (Radix in a `radix-*` project, Base UI in a `base-*` project). The part
  names and exports are the same on both bases; the props differ.
- Deltas that touch library code (from `.agents/skills/migrate-radix-to-base`, consumer-props
  and the per-family tables): menu `onSelect` to `onClick` plus `closeOnClick` (CheckboxItem and
  RadioItem default to staying open on Base UI); select `onValueChange(value | null, details)`
  and `position="popper"` to `alignItemWithTrigger={false}`; checkbox `checked="indeterminate"`
  to a separate `indeterminate` prop; slider `onValueChange` shape and `onValueCommit` rename,
  `inverted` gone; tooltip provider `delayDuration` to `delay`, `skipDelayDuration` gone;
  `asChild` to `render` everywhere; `onOpenChange` callbacks gain a second argument (compatible).
  Dialog, popover, collapsible, switch, radio, progress, badge, button, input, label, field,
  input-group, pagination, separator, skeleton, spinner, alert, native-select: name-compatible,
  no library change expected.
- Library files touching the differing parts (23): `ST_Tooltip.tsx`, `ShadcnTable.tsx`,
  `types.ts`, `menus/*` (7), `inputs/ST_FilterCheckbox.tsx`, `inputs/ST_SelectCheckbox.tsx`,
  `inputs/ST_FilterRangeSlider.tsx`, `inputs/ST_FilterTextField.tsx`,
  `inputs/ST_GlobalFilterTextField.tsx`, `inputs/ST_EditCellTextField.tsx`,
  `head/ST_TableHeadCellFilterContainer.tsx`, `head/ST_TableHeadCellFilterLabel.tsx`,
  `body/ST_TableDetailPanel.tsx`, `modals/ST_EditRowModal.tsx`, `toolbar/ST_LinearProgressBar.tsx`,
  `toolbar/ST_TablePagination.tsx`, `toolbar/ST_ToolbarAlertBanner.tsx`.
- One package, one `components.json` (`radix-nova`), one Storybook, one Vitest run, 401 tests.
  The registry is one `registry.json` per package, items addressed by name; the GitHub registry
  address has no per-style path, so a second base needs a second item name.

## Design

**Adapter layer, one shared library.** The MRT-shaped core (hooks, fns, utils, types, the
`ST_*` components that render table markup) stays base-agnostic. Every place that uses a
differing primitive prop moves behind a small internal module per primitive family under
`src/components/ui/shadcn-table/primitives/`: `menu.tsx`, `select.tsx`, `tooltip.tsx`,
`checkbox.tsx`, `slider.tsx` (only families with deltas; `ST_Tooltip` and `ST_ActionMenuItem`
are already half of this). Two implementations per file, `primitives/radix/<family>.tsx` and
`primitives/base/<family>.tsx`, same exported API. Library code imports
`./primitives/<family>`; the registry item decides which implementation lands at that path
(registry file `target` per item). Two items: `shadcn-table` (Radix, unchanged address) and
`shadcn-table-base` (Base UI). Locale and example items become base-neutral: they drop the hard
`registryDependencies` on the main item (the files only import `../types` and the barrel, which
either item provides) and the docs say "install the table first".

Rejected: a second full copy of the library per base (double maintenance); one item with
runtime base detection (the CLI has no hook); per-style item paths (unsupported for GitHub
registries).

## Phases

### 0. Spike (one agent, read-only on the repo, scratch app)

`shadcn init --template vite --base base --preset nova`, `shadcn add anindosarker/shadcn-table/shadcn-table`
(Radix item into a Base UI app), `tsc --noEmit`. Catalog every error: library file, line, part,
prop. Also run `storybook:build` is not possible there; instead render the basic, filtering,
editing and column-actions examples in the app and note runtime failures in the browser
(Playwright). Output: the delta inventory appended to this plan, and the list of primitive
families that need an adapter (expected five, confirm). Also check whether the `combobox` part
(already Base UI based in the radix-nova style) and `command` behave the same.

### 1. Adapter layer in the Radix build (refactor, no behavior change)

Introduce `primitives/<family>.tsx` with the Radix implementation only, move the 23 files onto
it. Acceptance: `tsc`, `lint`, 401 tests, `storybook:build`, `registry:build` produce an
identical `registry.json` apart from the new file entries; docs `lib:install` then page gate
`a` and `e` green. One commit per family.

### 2. Base UI implementations and the dev harness

- Base parts for development: `packages/shadcn-table/base/` holds its own `components.json`
  (`base-nova`) and `components/ui/*` installed by the CLI; nothing else lives there.
- A build switch: Vite and Vitest alias `@/components/ui` and `./primitives` to the base
  directories when `ST_BASE=base`; `pnpm test:base`, `pnpm storybook:base` (port 6007),
  `pnpm tsc:base` (a second tsconfig with the paths). Stories unchanged; they must pass on both.
- Write `primitives/base/<family>.tsx` against the consumer-props tables; fix stories that fail
  only on base (expected: menu close-on-click defaults, checkbox indeterminate, select null
  value, slider value shape, tooltip delays).
- Acceptance: 401 tests green in both modes, both Storybook builds, both tsc runs. CI `library`
  and `test` jobs become a matrix over `radix` and `base`.

### 3. Registry, install test, docs

- `scripts/build-registry.mjs` emits `shadcn-table-base` next to `shadcn-table`: same files
  except the primitives directory, same `registryDependencies` (bare names resolve per base),
  `dependencies` without `radix-ui` and with `@base-ui/react`. Locale and example items lose
  the main-item dependency. Root `registry.json` unchanged.
- CI `install` matrix gains `base`: `init --template vite --base base --preset nova`, add
  `shadcn-table-base`, a locale, `example-basic`, tsc, build.
- Docs: install page gets a Radix | Base UI tab on the add command (the init command differs
  by `--base`), the compatibility sentence changes, agents page and `skills/shadcn-table/SKILL.md`
  describe both items, README install block shows both. `lib/install.ts` gets the base item
  name. The docs app itself stays on Radix.
- Acceptance: registry validate, install job green for three scenarios, page gate green.

### 4. Release

Version `0.2.0`, release notes: Base UI support, item name, what is still Radix-only (nothing
expected), React Aria not supported. Tag `v0.2.0`.

## Non-goals

React Aria. TanStack Table v9. Visual changes to either base's parts. Docs site on Base UI.

## Risks

- Base UI menu items default to staying open on check; the show/hide columns menu relies on
  that, the column action menu relies on closing. Set `closeOnClick` explicitly per item in the
  adapter.
- Base UI `Select` with `null` values: `ST_FilterTextField` select branch assumes strings.
- Tooltip skip-delay is gone on Base UI; hover across toolbar icons waits the full delay.
  Accept, or set a shorter `delay` on base.
- `combobox` already depends on `@base-ui/react` in the Radix build, so both items carry that
  dependency; no conflict.

## Phase 0 findings (2026-10-19, scratch app in the session scratchpad `base-spike/`)

Setup: shadcn 4.22.1, `base-nova`, `@base-ui/react@1.9.0`, the Radix `shadcn-table` item plus a
locale and seven examples. tsc 64 errors from 13 root causes in 15 library files (31 are one
cascade from `ST_Tooltip.tsx`); runtime zero console or page errors, four behaviors wrong.

Adapter families, corrected: six, not five. `popover` joins (Base UI has no `PopoverAnchor`;
`ST_TableHeadCellFilterLabel` imports it, hard build break). Two base-neutral one-line fixes
instead of adapters: `dialog` (`ST_EditRowModal` forwards `(open, details)` to `onOpenChange`)
and `progress` (`?? null`). Files per family: tooltip 3 (`ST_Tooltip`, `ShadcnTable`,
`utils/style.utils.ts`), menu 6 (the five menus plus `ST_ShowHideColumnsMenuItems`), select 3
(`ST_FilterTextField`, `ST_TablePagination`, `ST_EditCellTextField`), checkbox and radio 3
(`ST_FilterCheckbox`, `ST_SelectCheckbox`, `types.ts`), slider 2 (`ST_FilterRangeSlider`,
`types.ts`), popover 1. 19 unique files.

Deltas per family: tooltip `asChild` to `render`, `delayDuration`/`skipDelayDuration` to Provider
`delay`, `disableHoverableContent` to Root `disableHoverablePopup`; menu `onCloseAutoFocus` to
`finalFocus`, trigger `asChild` to `render`, `onSelect` plus `preventDefault` to
`closeOnClick={false}` (show/hide columns menu closes on every toggle today); select
`position="popper"` to `alignItemWithTrigger={false}` (popup overlaps the trigger today), null
guard on `onValueChange`; checkbox `checked="indeterminate"` to the `indeterminate` prop
(renders as checked with invalid `aria-checked="indeterminate"` today), `onCheckedChange`
arity, the `CheckboxProps | RadioProps` cast in `ST_SelectCheckbox`; slider `onValueCommit` to
`onValueCommitted` (range filter never applies today), value shape; popover `PopoverAnchor` to
Positioner `anchor` (the base `PopoverContent` wrapper does not forward it, the adapter renders
its own Positioner). `asChild` appears in 7 files on `master` (tooltip, 5 menus,
`ST_ToolbarAlertBanner` Badge); the CLI rewrites element children to `render` on base installs
but drops it for `{children}` expressions, so the adapters own `render` themselves.

Other findings:
- The item ships `checkbox.tsx` as a forked file (minus icon for indeterminate) with a Radix
  import; a Base UI app gets a Radix checkbox and `radix-ui` in its `package.json`. The base
  item needs a Base UI fork (`data-indeterminate`), both forks ship from the item.
- Public types `CheckboxProps`, `RadioProps`, `SliderProps`, `DialogProps` in `types.ts` are
  `ComponentPropsWithRef<typeof Part>`; the adapters export base-neutral prop types instead.
- `combobox` and `command` are already Base UI based on both styles; bare dependencies, no change.
- Tooltip delay: Base UI has no skip-delay; set Provider `delay` in the base adapter, accept no
  skip grouping.
- Registry bug on every base: `example-advanced` ships `makeData.ts` importing `./TS` while the
  example file is renamed to `advanced.tsx` on install; tsc and build fail. Fix in
  `scripts/build-registry-items.mjs` (rewrite `./TS` imports to the renamed file) and verify
  every example with a `makeData.ts`.
- Install CI runs `pnpm tsc --noEmit` at the Vite template root, where the root tsconfig has
  `files: []`, so it checks nothing. Use `tsc -p tsconfig.app.json --noEmit`.
