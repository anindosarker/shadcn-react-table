# Local development

How the repository fits together and how to run each part. Contribution rules are in [CONTRIBUTING.md](CONTRIBUTING.md).

## Architecture

pnpm workspace (`pnpm-workspace.yaml`: `apps/*` and `packages/*`, minus `apps/material-react-table-docs`), task runner Turborepo (`turbo.json`).

```
shadcn-react-table/
├── registry.json                      root shadcn registry index (includes the two below)
├── packages/
│   ├── shadcn-react-table/            the library
│   │   ├── src/components/ui/shadcn-react-table/   table source (hooks, body, head, toolbar, menus, inputs, locales)
│   │   ├── src/components/ui/         the shadcn parts the library is built on (radix-nova generation)
│   │   ├── stories/, .storybook/      Storybook, one story file per component; Vitest browser tests run them
│   │   ├── scripts/build-registry.mjs writes registry.json; `shadcn build` renders public/r/*.json
│   │   ├── registry.json              library item + one item per locale
│   │   └── public/r/                  built registry items (committed)
│   └── material-react-table/          read-only upstream copy, used for parity diffs
└── apps/
    ├── test-shadcn/                   Vite playground, aliases the library to packages/shadcn-react-table/src
    ├── shadcn-react-table-docs/       docs site (Next.js 16 + fumadocs)
    │   ├── components/ui/shadcn-react-table/   committed copy of the library, installed through the registry
    │   ├── examples/<slug>/           113 example components (TS.tsx + makeData.ts)
    │   ├── registry.json              one registry item per example (generated)
    │   └── scripts/                   page gate, registry items, MRT docs sync, docs diff
    └── material-react-table-docs/     read-only upstream docs, source for the sync script
```

How the pieces connect:

- The library has no build step. It is distributed as source through the shadcn registry: the item `shadcn-react-table` lists every file under `src/components/ui/shadcn-react-table` with `registryDependencies` on the shadcn parts it imports. Consumers get the files copied into `components/ui/shadcn-react-table`.
- The playground imports the library source directly (vite and tsconfig alias `@/components/ui/shadcn-react-table`), so library edits hot-reload there without any install step.
- The docs site consumes the library the same way a user does: `lib:install` runs `shadcn add` against the built item and copies the files into the docs app. The copy is committed, so the docs build never depends on the package at build time.
- Every docs example is a registry item too (`apps/shadcn-react-table-docs/registry.json`, generated by `scripts/build-registry-items.mjs`). Its files are read straight from the repo by the GitHub namespace, so those items are not part of `public/r`.
- Two ways to reach the registry: the GitHub namespace `anindosarker/shadcn-react-table/<item>#<ref>` (reads `registry.json` from the repo at that ref, nothing to deploy) and a served `public/r` directory (local server or the deployed docs site).

## Prerequisites

- Node.js 20.9 or newer.
- pnpm 10. `packageManager` in `package.json` pins the version; `corepack enable` picks it up.
- Chromium for Playwright (library tests and the docs page gate): `pnpm --filter shadcn-react-table exec playwright install --with-deps chromium`.

```bash
git clone https://github.com/anindosarker/shadcn-react-table.git
cd shadcn-react-table
pnpm install
```

## Library (`packages/shadcn-react-table`)

```bash
pnpm storybook                                   # Storybook on http://localhost:6006
pnpm --filter shadcn-react-table tsc             # type check
pnpm --filter shadcn-react-table lint
pnpm test                                        # Vitest browser mode over the stories
pnpm --filter shadcn-react-table storybook:build
```

CI runs exactly these four checks (`.github/workflows/ci.yml`, jobs `library` and `test`). Format with `pnpm prettier --write <files>` or `pnpm format`.

## Playground (`apps/test-shadcn`)

```bash
pnpm --filter test-shadcn dev
```

Vite prints the port. Demos live in `src/demos`, the entry is `src/App.tsx`. Playwright checks for the playground and Storybook are in `.playwright/`.

## Registry

### Build

```bash
pnpm registry:build      # packages/shadcn-react-table/registry.json + public/r/*.json
pnpm registry:items      # apps/shadcn-react-table-docs/registry.json (example items)
```

Run `registry:build` after any file is added to or removed from the library; run `registry:items` after an example changes its imports or a new example is added. Both outputs are committed.

### Run the registry locally and install it in a test project

Terminal 1, repo root:

```bash
REGISTRY_BASE_URL=http://localhost:5310/r pnpm registry:build
pnpm registry:serve                              # serves packages/shadcn-react-table/public on http://localhost:5310
```

`REGISTRY_BASE_URL` makes the locale items depend on the local library item instead of the GitHub one. It rewrites the committed `public/r/*.json`; revert with `git checkout -- packages/shadcn-react-table/public` before committing.

Terminal 2, in a project that has run `shadcn init` (Tailwind v4). Add a namespace for the local server to its `components.json`:

```json
"registries": {
  "@srt": "http://localhost:5310/r/{name}.json"
}
```

Then install:

```bash
pnpm dlx shadcn@latest add @srt/shadcn-react-table
pnpm dlx shadcn@latest add @srt/shadcn-react-table-locale-de   # optional, one item per locale code
```

The URL form works without the namespace: `pnpm dlx shadcn@latest add http://localhost:5310/r/shadcn-react-table.json`.

Re-run the `add` command after library changes (rebuild first). The CLI overwrites the files under `components/ui/shadcn-react-table` and the shadcn parts it depends on.

### Install from a pushed branch (no local server)

```bash
pnpm dlx shadcn@latest add anindosarker/shadcn-react-table/shadcn-react-table#<branch-or-sha>
pnpm dlx shadcn@latest add anindosarker/shadcn-react-table/example-basic#<branch-or-sha>
```

The example items only resolve this way; they pin the library dependency to the branch in `apps/shadcn-react-table-docs/lib/shared.ts` (`gitConfig.branch`).

### Validate

```bash
pnpm --filter shadcn-react-table exec shadcn registry validate "anindosarker/shadcn-react-table#<branch-or-sha>"
pnpm --filter shadcn-react-table-docs exec shadcn add "anindosarker/shadcn-react-table/shadcn-react-table#<branch-or-sha>" --dry-run
pnpm --filter shadcn-react-table-docs exec shadcn add "anindosarker/shadcn-react-table/example-basic#<branch-or-sha>" --dry-run
```

Same commands as the CI job `registry`. For an example item before pushing, `node apps/shadcn-react-table-docs/scripts/build-registry-items.mjs --resolve <dir>` writes resolved item files that `shadcn add <file> --dry-run` accepts.

## Docs site (`apps/shadcn-react-table-docs`)

```bash
pnpm --filter shadcn-react-table-docs dev          # http://localhost:5320
pnpm --filter shadcn-react-table-docs types:check  # next typegen + tsc
pnpm --filter shadcn-react-table-docs build
```

### Update the library copy in the docs

```bash
pnpm registry:build
pnpm --filter shadcn-react-table-docs lib:install
git checkout -- apps/shadcn-react-table-docs/app/global.css
```

`lib:install` is `shadcn add` against the built item file. The item carries a `css` entry (the table's keyframes), so the CLI also re-serialises `app/global.css`; the checkout restores it. Only `components/ui/shadcn-react-table` should change.

### Page gate

Playwright assertions for every docs page, in clusters `a` to `e` (`scripts/page-checks/<cluster>.mjs`), against a running dev server:

```bash
cd apps/shadcn-react-table-docs
node scripts/check-pages.mjs --base http://localhost:5320        # all pages
node scripts/check-pages.mjs e --base http://localhost:5320      # one cluster
```

### Content sync with Material React Table

`node scripts/sync-mrt-docs.mjs` regenerates the MDX pages from `apps/material-react-table-docs`; `pnpm --filter shadcn-react-table-docs docs:diff` reports drift against the allow list in `scripts/docs-diff.allow.json`.

### Known file churn

- Next.js appends `<distDir>/types/**/*.ts` entries to `tsconfig.json` on every `dev` and `build`. Keep only the default `.next/types/**/*.ts` and `.next/dev/types/**/*.ts` pair in the committed file.
- `NEXT_DIST_DIR=<dir>` picks a separate `.next` directory, for running several dev servers from one checkout.
